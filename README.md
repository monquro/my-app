# 숏폼 4계정 주간 성과 — SQL 앱 (동료용)

매주 월요일에 파일을 «내 파일로» 탭에 넣고, 준비된 질문을 실행해 주간 표를 뽑는 앱입니다. Claude 없이 씁니다.
앱에 처음 들어 있는 데이터는 연습용 가상 데이터입니다(실제 회사 · 계정과 관계없음).

## 쓰기 전에

1. **파일 이름에 «목표» · «계정주간» · «게시물» 이 들어 있어야 합니다.** 이름으로 표를 고릅니다 — «목표» → targets · «계정주간» → account_weekly · «게시물» → posts. 한 이름에 둘 이상 들어 있으면 이 순서로 먼저 맞는 표로 갑니다. 셋 다 없으면 그 파일은 넣어지지 않습니다.
2. **파일을 하나라도 넣으면, 질문에 나오는 표의 파일을 모두 넣어야 질문이 돕니다.** 빠진 표를 가상 데이터로 채우지 않고 멈춥니다. weekly_kpi · summary_12w 는 목표 · 계정주간 · 게시물 셋, top_posts 는 계정주간 · 게시물 둘이 필요합니다. 계정별 게시물 파일은 **한꺼번에** 넣으면 하나로 합쳐집니다. 같은 표의 파일을 다시 넣으면 앞서 넣은 것을 통째로 대신하므로, 다시 넣을 때도 그 표의 파일을 전부 함께 넣습니다.
3. **파일은 브라우저 밖으로 나가지 않습니다.** 읽기도 계산도 이 화면 안에서 합니다. «문장으로 묻기»(SQL 만들기 (AI))를 누르면 질문 문장과 표 설명(schema.json — 가상 데이터의 열 이름과 값 예)만 서버 함수(api/sql.py)를 거쳐 Google Gemini 로 갑니다. 내 파일의 내용은 가지 않습니다. 질문 문장에 적은 글자는 그대로 가니, 내 파일의 숫자나 이름을 문장에 적지 마십시오.
4. **질문 옆 기댓값(✓ · ✕)은 가상 데이터 기준입니다.** 내 파일로 돌릴 때 ✕ 가 떠도 오류가 아닙니다 — 앱도 «내 파일에서는 달라도 됩니다» 라고 알려 줍니다.
5. **TT와 IG 조회는 더하지 않습니다. 카드 조회와 게시물 조회도 더하지 않습니다.** 세는 방식이 같은지 확인되지 않았고(TT · IG), 카드 조회는 계정이 그 주에 받은 조회, 게시물 조회는 그 주에 올린 게시물의 누적 조회라 다른 숫자입니다(docs/데이터_사전.md).
6. **게시물 숫자는 올린 날부터 기록 전날까지의 누적이라, 월요일에 뽑은 파일에서 지난주 금~일 게시물은 덜 자란 숫자다.** 상위 콘텐츠를 볼 때 나이 열을 같이 봅니다.

## 매주 만드는 법

열 이름은 [docs/데이터_사전.md](docs/데이터_사전.md) 그대로 씁니다. 날짜 열은 YYYY-MM-DD 로 적습니다.

1. **목표.xlsx** 는 한 번 만들고, 목표가 바뀔 때만 고칩니다. 열: account · brand · platform · target_followers · weekly_post_target(주당 업로드 목표). 계정마다 한 행입니다.
2. **계정주간.xlsx** 에 지난주 4행(A_IG · A_TT · B_IG · B_TT)을 더합니다 — 화면 카드의 팔로워 · 조회 · 인터랙션 · 업로드 수. 열: account · week_start(그 주 월요일) · followers(그 주 일요일 팔로워) · views · interactions · posts_count(카드의 업로드 수를 옮겨 적은 값). posts_count 는 사람이 옮겨 적는 값이라 대조용입니다 — 업로드 수는 게시물 파일에서 셉니다.
3. **Metricool** 에서 계정마다 지난주(월~일) 게시물 목록 CSV를 받아, 이름만 «게시물_계정_받은날짜»(예: `게시물_A_IG_2026-11-30.csv`)로 바꿉니다.
   - 계정 열과 기록일(recorded_on)은 CSV에 그 열이 없을 때 앱이 파일 이름에서 채웁니다. 파일 이름에 날짜가 없으면 파일 수정 날짜를 쓰니, 이름에 날짜를 적어 두십시오.
   - 날짜는 CSV를 받은 날로 적습니다. Metricool 숫자는 그 전날까지의 누적이기 때문입니다(게시물 나이 = 기록일 − 올린 날).
   - CSV 열: post_id · posted_date · format · title · category · views · likes · comments · shares · saved(IG만) · full_video_rate(TT만). 앱은 열 이름을 바꿔 주지 않습니다.
4. **목표 · 계정주간 · 계정별 게시물 파일을 «내 파일로»에 한꺼번에 넣고**, weekly_kpi · top_posts 를 실행합니다(summary_12w 는 달마다). 파일 하나만 고쳤어도 다시 넣을 때는 전부 한꺼번에 넣습니다.
   - weekly_kpi · top_posts 는 계정주간에서 가장 늦은 주를 보고, 그 주에 올린 게시물을 게시물 파일에서 찾습니다.
   - summary_12w 는 넣은 게시물 전부를 세고 목표를 12주로 곱해 달성률을 냅니다. 12주치 게시물 파일이 모두 들어 있어야 맞는 값입니다.
5. 결과를 Asana «SNS 성과 분석 - n월 n주차» 의 ⓐ · ⓒ 에 옮깁니다(weekly_kpi → ⓐ 전체 성과 표 · top_posts → ⓒ 상위 콘텐츠 표).

## 넣은 뒤 화면에서 볼 것

- 파일마다 ✓ 또는 ✕ 가 뜹니다. ✓ 는 «파일에서 읽은 줄»과 «표에 올라간 줄»이 같을 때입니다(여러 파일이면 줄 합과 합친 표의 줄이 같을 때). ✕ 에는 이유가 적힙니다.
- 엑셀 파일에 시트가 여러 개면 첫 시트만 읽고, 그렇다고 알려 줍니다.
- 쓰는 동안 인터넷이 필요합니다(데이터 엔진을 cdn.jsdelivr.net 에서 받습니다).
- 페이지를 새로고침하면(«원래 데이터로 돌아가기»도 같습니다) 넣은 파일이 사라집니다. 다음에는 전부 다시 넣습니다.
